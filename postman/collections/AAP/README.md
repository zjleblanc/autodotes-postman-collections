# AAP Collection

Postman v3 collection for the Ansible Automation Platform instance at
`https://ansible.autodotes.com`. Generated by crawling the gateway's
federated API index (`GET /api/`) and every top-level API it lists:

```json
{
  "gateway": "/api/gateway/",
  "controller": "/api/controller/",
  "eda": "/api/eda/",
  "galaxy": "/api/galaxy/",
  "lightspeed": "/api/lightspeed/",
  "metrics": "/api/metrics/"
}
```

## Structure

One folder per top-level API, holding every endpoint discovered under it:

| Folder | Requests | Source |
| --- | --- | --- |
| `Gateway API` | 141 | DRF breadth-first crawl |
| `Controller API` | 557 | DRF breadth-first crawl |
| `Metrics API` | 23 | DRF breadth-first crawl |
| `EDA API` | 121 | OpenAPI spec (`/api/eda/v1/openapi.json`) |
| `Galaxy API` | 438 | Merged OpenAPI specs (see below) |
| `Lightspeed API` | 1 | Placeholder -- service unavailable (see below) |

Within each API folder, sub-folders mirror the URL path (e.g.
`Controller API/job_templates/credentials/`), and each endpoint/method pair
is its own `*.request.yaml` (`List X`, `Create X`, `Get X`, `Update X`,
`Partial Update X`, `Delete X`, or an action-specific name like
`Cancel Job` / `Launch Job Template`).

## Auth

Auth (`Bearer {{aap_token}}`) and `{{aap_base_url}}` are declared once on the
top-level `AAP` collection (`.resources/definition.yaml`) and inherited by
every folder and request beneath it -- set `aap_token` once in your
environment (e.g. `postman/environments/zleblanc-main.environment.yaml`)
rather than per-API.

## How each API was discovered

- **gateway, controller, metrics** -- self-describing DRF REST APIs with no
  published schema. Crawled breadth-first from the versioned API root:
  `OPTIONS` on each endpoint supplies allowed HTTP methods (and, where
  available, writable field schemas used to build example request bodies);
  `GET` samples one item and follows its `related` links to discover
  sub-resources. Endpoints are deduplicated by replacing numeric/slug ID
  segments with a single `{id}` template, which also prevents infinite loops
  on cross-links (every resource's `created_by` pointing back to `/users/`).
  **Caveat:** if a resource has zero items on this instance, its detail and
  sub-resource endpoints can't be sampled and won't appear here.

- **eda** -- generated directly from its published OpenAPI document
  (`/api/eda/v1/openapi.json`, 84 paths). Request bodies and query params are
  built from the spec's schemas/parameters.

- **galaxy** -- Automation Hub exposes two overlapping OpenAPI documents:
  `/api/galaxy/v3/openapi.json` (curated, standard `{param}` placeholders)
  and the underlying Pulp app's `/api/galaxy/pulp/api/v3/docs/api.json`
  (broader, 607 paths). This collection merges both specs' concrete
  `/api/galaxy/...`-prefixed paths. **Excluded:** Pulp's `{xxx_href}action/`
  style paths (e.g. `{ansible_collection_href}add_role/`), which require an
  already-fetched resource href rather than a fixed URL template, and a
  handful of paths mounted outside `/api/galaxy/` (`/pulp_ansible/...`,
  `/ansible/collections/`, `/token/`).

- **lightspeed** -- every probed path (`/api/lightspeed/`, `/v1/`, `/v0/`,
  `/health/`) returned `404` on this instance, so it's not deployed/enabled
  here. The folder has a single `Check Lightspeed Availability` request
  documenting that; re-run the crawler for `lightspeed` once the service is
  enabled.

## Regenerating

```bash
source .venv/bin/activate
AAP_POSTMAN_TOKEN_READONLY=... python scripts/crawl_aap_api.py            # all APIs
AAP_POSTMAN_TOKEN_READONLY=... python scripts/crawl_aap_api.py controller # one API
```

The script is idempotent per API folder but additive across runs (it won't
delete requests for endpoints that disappear); delete an API's folder under
`postman/collections/AAP/` before re-running it for a clean rebuild.

## Known limitations

- Crawled with a read-only token against live data on one instance at one
  point in time -- sparsely-populated resources may be under-documented (see
  caveat above), and any endpoint requiring elevated permissions beyond the
  token's scope wouldn't be reachable during discovery.
- Example bodies are structurally representative (correct field names/types)
  but use placeholder values -- replace them with real data before sending
  write requests.
- `postman collection lint postman/collections/AAP` passes with no issues as
  of generation.
